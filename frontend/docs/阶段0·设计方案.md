## 1. 技术选型的补充决策

硬约束（Vue 3 / TS strict / Vite / Pinia / Vue Router 4 / Element Plus / 高德 2.0 + Loca 2.0 / ECharts 5 / 原生 WS / axios）全部照单接受，以下是我在自由项上的决定。

| 事项 | 决定 | 理由 |
|---|---|---|
| 包管理器 | **pnpm** | 严格 `node_modules` 结构杜绝幻影依赖——本项目类型定义是唯一契约真相，依赖解析必须确定性；后期若拆 `packages/map-kernel` 可直接上 workspace |
| CSS 方案 | **CSS 变量令牌层 + UnoCSS (preset-wind)** | 地图浮层大量一次性布局，写 BEM 会产生大批只用一次的语义类；令牌层用原生 CSS 变量而非 Uno 主题，是为了让 Element Plus 的 `--el-*` 变量能直接引用同一批值，运行时切深色不需重新构建。**硬规则：任何数据色（色带、图例、系数带）禁止用 Uno 原子类，只能来自 `tokens/data-color.ts`**，否则图例与地图必然失同步 |
| 图标 | **Iconify + `@iconify-json/ph`（Phosphor）按需内联** | Element Plus 自带图标覆盖不到图层/时间轴/坐标系这类领域概念；Phosphor 的细线风格与「图纸」方向一致。地图控件图标另行手绘 SVG，因为要跟 Loca 的像素密度对齐 |
| 日期 | **dayjs** + `utc` / `timezone` 插件 | Element Plus 已依赖，零额外体积。**内部约定：时间轴与所有状态一律存 epoch 毫秒数字，只在渲染层格式化**——时间轴要做逐帧/倍速运算，字符串时间是性能与时区双重陷阱 |
| 表格虚拟滚动 | **`el-table-v2`**，复杂场景降级 `@tanstack/vue-virtual` | 数据预览只取前 N 行，本就不需要虚拟滚动；真正需要的是残差明细表（可达数万行），`el-table-v2` 够用且不引入第二套表格心智 |
| Web Worker | **Comlink + Vite `?worker`**，返回 `Transferable` 的 TypedArray | 手写 `postMessage` 协议在坐标转换这种高频调用上会很快失控。**约定：Worker 边界只传 TypedArray 和数字，不传对象数组**——`[{lng,lat},...]` 形态的 10 万点结构化克隆开销就足以掉帧 |
| 服务端状态缓存 | **TanStack Query (vue-query)**，与 Pinia 分工 | 若把请求缓存塞进 Pinia，每个 store 都会长出一套 `loading/error/stale/refetch`。分工规则见 §5：**Pinia 只放「用户决定的东西」，vue-query 只放「服务端说的东西」** |
| Mock 层 | **MSW 2.x** | 比 `vite-plugin-mock` 更贴近真实网络层（走 Service Worker，能被 DevTools Network 看到），而且**同一套 handler 可以直接给 Vitest 复用**；MSW 2.x 已支持拦截 WebSocket，训练进度推送也能 mock，这是选它的决定性理由 |
| 字段映射校验 | **独立纯函数规则引擎**，不绑 Element Plus 表单校验 | 校验规则要能被单测（阶段 5 硬性要求），也要能在「配置模板」导入时离开 UI 单独跑一遍。绑在表单组件上就两条都做不到 |

## 2. 设计令牌

### 2.1 方向陈述

这个界面的原型不是后台管理系统，是**分析图纸**：底下一张地图，上面叠若干张半透明的蜡纸（分析者过去真的用聚酯薄膜叠在图幅上作业）。面板浮在地图之上而非切割地图，边缘是一根发丝线加一层背景模糊，而不是投影阴影——因为地图底色从深海到亮城区剧烈变化，普通阴影在浅底上是脏的、在深底上是不存在的。

刻意避开的方向：米白底 + 高对比衬线 + 陶土色（当下 AI 生成设计的通用相貌），以及纯黑底 + 单一荧光绿。前者与「科学制图」无关，后者会跟数据色带抢注意力。

### 2.2 色（6 个命名值）

```css
:root {
  --c-north:   #0B1F2A;  /* 磁北 · 浅色下的正文与线，深色下的基面 */
  --c-mylar:   #F2F4F3;  /* 蜡纸 · 浅色基面。冷偏，不是米白 */
  --c-graphite:#5B6770;  /* 石墨 · 次级文字、分隔线、格网 */
  --c-isoline: #0F7C7B;  /* 等值青 · 发散色带负端；同时是「已完成/已发布」状态色 */
  --c-ochre:   #C2611D;  /* 赭土 · 发散色带正端 */
  --c-signal:  #6B4DF0;  /* 电紫 · 唯一交互色 */
}
```

三条不可协商的用色纪律：

1. **`--c-signal` 永不进入地图画布与图例。** 否则用户无法判断屏幕上一块紫色是「可以点」还是「数值高」。交互色与数据色必须互斥，这是地图类产品与普通后台最实质的差别。
2. **发散色带在灰度下仍要可读。** 青↔赭是蓝–橙轴，对红绿色觉障碍安全；但对蓝黄色觉障碍（三色觉异常）不够，所以两端明度都低、零点明度最高——去色后仍呈「深—浅—深」，形状本身携带信息。
3. **零点明度跟随基面。** 浅色模式零点用 `#EFE9DD`，深色模式换 `#2A3138`。零点若比背景亮，整张系数图会看起来处处有信号。

数据色带（`tokens/data-color.ts`，唯一出口）：

- **发散**（回归系数、残差）：`#0F7C7B → 零点 → #C2611D`，11 阶
- **连续**（浓度、房价、密度）：靛蓝单色明度阶 `#EEF1F8 → #2B3A67 → #0B1436`
- **同屏并置规则**：一屏最多一条发散色带；若发散层与连续层同时可见，连续层强制切为单色明度阶并降不透明度至 ≤60%
- 语义色只补一个 `--c-alarm: #B5323C`，**仅用于错误，绝不用作数据色**

### 2.3 字

三个角色，中西文分工不同——中文没有可用的窄体，硬套会得到拉伸变形的假窄体，所以：**西文靠字宽区分角色，中文靠字重与字距区分角色。**

| 角色 | 西文 | 中文 | 用法 |
|---|---|---|---|
| 显示 Display | **Barlow Condensed** 600 | 思源黑体 SC 700，`letter-spacing: .06em` | 页面标题、图幅标注式眉标（全大写 + 宽字距）、关键数字。窄体 + 宽字距是地形图与气象图图廓外注记的字体语言 |
| 正文 Body | **Barlow** 400/500 | 思源黑体 SC 400 | 说明、表单标签、按钮。与显示体同族不同宽，形成宽度对比而非风格拼贴 |
| 数据 Data | **IBM Plex Mono** 400/500，`tabular-nums` | 同左（中文极少出现在数据位） | 表格数值、坐标、指标、日志。科学界面里小数点对不齐就是缺陷 |

字阶（1.25 比例，`clamp()` 响应）：`11 / 12 / 14 / 16 / 20 / 25 / 32 / 40`。11px 只给图例与坐标读数，是等宽体，实测可读。

### 2.4 间距 / 圆角 / 层级

- **间距**：4 基数 → `4 8 12 16 24 32 48 64`。浮层内边距固定 16，浮层之间外边距固定 12。
- **圆角**：`0`（图例色块、色带）/ `2`（输入、标签）/ `6`（卡片、按钮）/ `12`（蜡纸浮层）/ `999`（时间轴滑块头）。色带用 0 是因为圆角会让相邻分级之间出现视觉缝隙，破坏连续性。
- **层级**：不用常规投影。

```css
--e0: none;                                          /* 嵌入地图的元素 */
--e1: 0 0 0 1px var(--edge), 0 2px 12px rgb(0 0 0/.10),
      backdrop-filter: blur(12px) saturate(1.1);     /* 蜡纸浮层 */
--e2: 0 0 0 1px var(--edge), 0 8px 24px rgb(0 0 0/.16);  /* 下拉、气泡 */
--e3: 0 24px 64px rgb(0 0 0/.28);                    /* 模态 */
```

`--edge` 在浅色是 `rgb(11 31 42 / .12)`、深色是 `rgb(255 255 255 / .14)`——发丝线是浮层在任何底图上都能被认出来的最小保证，模糊只是补充。

### 2.5 深色模式

令牌层双套值（`:root` / `[data-theme="dark"]`），不做事后覆盖。三处联动：底图样式切 `amap://styles/darkblue`↔`whitesmoke`；数据色带切同色相高明度变体；`--edge` 与色带零点同步。默认跟随系统，用户选择持久化。

### 2.6 记忆点：系数带 β-Ribbon

**平台被记住的应该是「同一个变量在不同地方价值不同」。所有设计上的大胆之处只花在这一个部件上，其余保持克制。**

规则很简单：**在这个平台上，回归系数永远不以单个数字出现。** 任何本该打印 `β = 0.42` 的位置，打印的是一条带——横轴是系数取值，零点固定居中锚定，发散色带填充，分布密度决定高度，当前点位的局部值用一根竖标记标出。

```
   负 ◄──────────────┃──────────────► 正
        ▒▓█████▓▒         ← GNNWR：一条带，宽度就是空间非平稳性
                ┃ +0.61   ← 当前点位
   ─────────────╂───────  ← OLS：塌缩成一根线 +0.24
```

这个部件同时解决三件事：把「为什么不用黑箱模型」变成不需要解释的视觉事实；把精度对比里 OLS 与 GNNWR 的差别从表格数字变成形状差别；给非编程背景的用户一个不需要统计训练就能读的抽象。

- **出现位置**：训练监控、看板浮层、精度对比表每一行、结果摘要卡、地图点击弹窗、PDF 报告
- **三档尺寸**：inline（h=14，嵌表格单元格）/ card（h=48）/ hero（h=96，看板主浮层）
- **数据输入**：全域分位数摘要 `q05 q25 q50 q75 q95 + min max` + 可选局部值（分布摘要由后端给还是前端算，见协商清单 §9-3）
- **无障碍**：不依赖颜色——零点有实线锚、局部值有几何标记、focus 时朗读数值文本；`prefers-reduced-motion` 下取消带内扫描动画

## 4. 状态管理划分

分工总则：**Pinia 只放「用户决定的东西」和「跨组件共享的会话状态」；服务端返回的数据一律进 vue-query 缓存，不进 Pinia。**

| Store | 持有 | 关键点 |
|---|---|---|
| `auth` | token、角色、过期时间 | 无感刷新单飞（并发 401 只发一次刷新，其余排队重放） |
| `project` | 当前项目、`scenario_type` | 场景类型只影响默认值与文案，**不影响任何解析逻辑**（禁止事项 1） |
| `dataset` | 上传队列、分片进度、字段推断结果与人工覆盖、原始 CRS 声明、状态机 | 人工覆盖必须与自动推断分开存，才能显示「你改了 2 处」并支持一键还原 |
| `modeling` | 向导 6 步草稿、校验结果、配置模板 | 草稿按 `projectId` 持久化到 localStorage，回退不丢配置靠它 |
| `task` | taskId → 任务状态机、WS 连接生命周期、轮询兜底、重连退避计数 | 跨标签页用 `BroadcastChannel` 选主：只有一个标签持有 WS，其余订阅广播。否则 5 个标签 = 5 条连接 |
| `layer` | 图层集合、显隐、透明度、层序、图例分级方式 | 图例与分级同源同一份状态，从结构上杜绝图例与地图不一致 |
| `timeline` | 当前时刻（epoch ms）、播放状态、倍速、帧序列 | 独立成 store 而非塞进 layer：时间轴要同时驱动地图、图表、系数带 |
| `selection` | 选中要素、刷选集合、悬停要素 | **联动总线**。地图刷选→图表过滤、图表点击→地图定位，都只经过它，组件之间零直连 |
| `ui` | 主题、浮层开合、reduced-motion | — |

`layer + timeline + selection` 三者构成看板的共享内核，联动逻辑封装为 `useMapChartLink()` 组合式函数，组件只订阅不直接改对方。

## 5. 坐标系类型方案

后端以 WGS84/CGCS2000 计算，高德底图是 GCJ-02。目标不是「记得转换」，而是**让漏转换写不出来**。

### 5.1 标量路径：品牌类型

```ts
// shared/geo/crs.ts —— 全项目唯一允许做坐标变换的文件
declare const CRS_TAG: unique symbol;

export type CRS = 'WGS84' | 'GCJ02' | 'CGCS2000';

/** 带坐标系标签的坐标。运行时就是 [lng, lat]，零开销 */
export type Coord<C extends CRS> = readonly [number, number] & { readonly [CRS_TAG]: C };

/** 唯一构造入口：必须显式声明这对数字是什么坐标系 */
export function coord<C extends CRS>(crs: C, lng: number, lat: number): Coord<C>;

/** 唯一转换入口 */
export function project<F extends CRS, T extends CRS>(from: F, to: T, c: Coord<F>): Coord<T>;
```

渲染层只接受 GCJ-02：

```ts
// map/kernel/layers.ts
export function addPoints(points: ReadonlyArray<Coord<'GCJ02'>>): void;
```

于是 `addPoints(wgsPoints)` 是**编译错误**，而不是一份偏移 500 米的地图。CGCS2000 与 WGS84 在本项目精度下视作等同，但仍是两个类型——等同关系写在 `project()` 里一次，不散落在调用处。

### 5.2 批量路径：带标签的缓冲区

10 万个品牌类型元组的开销不可接受，批量数据用结构数组：

```ts
export interface CoordBuffer<C extends CRS> {
  readonly crs: C;
  readonly xy: Float64Array;   // [lng, lat, lng, lat, ...]
  readonly count: number;
}
```

转换在 Worker 内对 `Float64Array` 就地执行，`Transferable` 零拷贝回主线程。类型标签保住了编译期安全，TypedArray 保住了性能。

### 5.3 三道防线

1. **编译期**：品牌类型（上）
2. **构建期**：ESLint `no-restricted-imports` 白名单——除 `shared/geo/**` 外，任何文件 import 转换函数直接报错。转换逻辑物理上无法散落
3. **运行期（仅 dev）**：`assertCrs(buf, 'GCJ02')` 在图层入口断言；另有「离岸哨兵」——入库前抽样 200 点，若落在陆地边界外比例 > 5%，直接提示坐标系可能选错并给出一键切换

栅格图层（WMS 曲面）无法用以上任何一条解决，它是 §7 风险 1。

## 6. 性能预算与验证方式

| 指标 | 预算 | 怎么验 |
|---|---|---|
| 10 万点地图交互 | 连续 pan/zoom 5 秒，帧时长 **p95 ≤ 33ms**（≈30 FPS） | Playwright 驱动固定轨迹的 pan/zoom 脚本 + CDP `Performance` 域采帧；结果写入 CI 产物，回归即失败。不用肉眼看 `stats.js` |
| 首屏可交互 | **< 3s**（4G 节流 / 中端机） | 自埋点 `performance.mark('map:interactive')` 而非只信 Lighthouse TTI——本产品的「可交互」定义是地图能拖动，不是 DOM 就绪 |
| 首屏 JS | ≤ 180KB gzip | `size-limit` 卡 CI |
| 地图相关 chunk | ≤ 300KB gzip，且**仅在进入含地图路由时加载** | 高德 SDK 动态 `import()`，不进 index.html |

达标手段：路由级懒加载、Element Plus 与 ECharts 按需引入、Loca 分帧渲染、Worker 解析、视野变化 200ms 防抖 + `AbortController` 取消过期请求、瓦片 LRU（上限按内存估算而非固定条数）。

## 7. 三个最大技术风险

### 风险 1 · 栅格曲面与高德底图的系统性偏移 —— 最高

矢量点可以逐点纠偏，**栅格瓦片不行**。GeoServer 若出 WGS84 切片，叠在 GCJ-02 底图上会有约 300–600m 的位移，且在城市尺度下肉眼可见、在论文截图里是硬伤。三条路线：

| 路线 | 做法 | 代价 |
|---|---|---|
| A（推荐） | 服务端在 GeoServer 侧配置 GCJ-02 自定义投影 / 出图时纠偏，前端直接贴 | 需后端配合，进协商清单 §9-4 |
| B | 前端按 0.05° 格网做偏移近似，用 canvas 重采样 | 边缘接缝、缩放级别切换抖动、CPU 开销大；只作为演示兜底 |
| C | 曲面视图切换到 WGS84 底图（天地图或自托管 MapLibre），矢量点同步切换 | 与「高德为硬约束」冲突，需你确认是否可作为**局部**例外 |

**阶段 0 决定**：地图内核按「可替换渲染后端」抽象（`MapAdapter` 接口），先实现高德适配器，为路线 C 保留插口。这也顺带覆盖问题 5 的内网场景。

### 风险 2 · 结果数据量压垮前端

10 万点 × 8 变量 = 80 万系数，若 `/result` 一次性返回 JSON，解析就要秒级、内存要几百 MB。缓解：结果层不走一次性 JSON，改走 `/spatial/tiles` 的 bbox + time 增量通道（依赖问题 2 的答案）；全域分布摘要（系数带需要的分位数）优先请后端算，前端只在样本量 < 2 万时兜底自算；解析全程 Worker + TypedArray。

**若后端确认无法提供分页**：阶段 1 就要把结果访问封成 `useCoefficientField()` 接口，实现可换但调用点不变，避免后期返工穿透到所有视图。

### 风险 3 · 契约漂移

后端未就绪，Mock 一定会与真实接口分叉，且通常在联调前一周才暴露。缓解：**TypeScript 类型是唯一真相**，Mock 夹具由类型生成（`@anatine/zod-mock` 或手写工厂函数），类型一改夹具即崩；每个接口写一条契约测试，联调时对真实响应跑同一套断言；对不确定字段做 capability detection + 优雅降级（如 §3.4 的系数带演进栏），而不是假定其存在。

*次级观察项（暂不列为风险）*：时间轴播放 + WS 推送 + 视野增量请求三者并发时的状态一致性。计划用「时间轴播放期间暂停视野增量请求」的简单策略先行，阶段 4 复评。

## 8. 自我批判：三处通用默认，已改掉

### 8.1 「左侧全局菜单 + 面包屑」→ 项目内阶段轨

**原本会怎么写**：左侧一棵功能树（数据管理 / 模型管理 / 可视化 / 系统设置），顶部面包屑。
**为什么是默认**：这套导航表达的是「系统有哪些功能」，适合功能集合型后台。
**改成什么**：导航降级为项目内的 5 节点阶段轨，节点带完成态与解锁条件。
**理由**：这个产品本质是一条流水线——没有数据就不能建模，没有训练完成就没有结果可读。用户真正需要导航回答的问题是「我在第几步、下一步能不能走、卡在哪」，功能树一个都答不了。面包屑在 5 个节点的场景里是纯冗余，删除。

### 8.2 「上传后展示表格预览」→ 地图优先预览

**原本会怎么写**：上传成功 → 一张前 N 行的数据表 → 底下挂个「查看地图分布」按钮。
**为什么是默认**：任何数据平台都这么做，因为它对非空间数据是对的。
**改成什么**：上传成功后地图占据主区域并立即打点，表格默认收起为一行「前 20 行 ▸」。
**理由**：空间数据最高频的致命错误是坐标系错配和经纬度写反，症状是点全部落进几内亚湾、或整体偏移几百米。**这两种错误在表格里 100% 看不出来，在地图上 1 秒就能看出来。** 顺带把「离岸哨兵」的警告和一键切换坐标系放在同一视野里，让发现问题与修复问题不隔页面。

### 8.3 「进度条 + loss 曲线」的训练监控 → 加系数带演进

**原本会怎么写**：进度条 + 双线 loss 曲线 + epoch 计数，完事。
**为什么是默认**：所有 ML 平台的训练页都长这样。
**改成什么**：右栏并列展示各自变量系数带随 epoch 的演进。
**理由**：目标用户是规划师和地理研究生，**他们看不懂 loss 下降意味着什么**，但完全看得懂「地铁距离的影响正在南城和北城分化」。同一块屏幕面积，给工程指标还是给专业语义，是这个产品对不对得起「零代码」定位的分水岭。此项依赖 WS payload 扩展，未就绪时整栏降级，不影响主流程。
