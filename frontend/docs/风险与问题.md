# 风险 1 · 栅格曲面与高德底图的系统性偏移

## 问题

后端统一以 WGS84/CGCS2000 计算，高德底图要求 GCJ-02。矢量点可以逐点纠偏（`shared/geo` 已完整实现），**栅格瓦片不行**——它是一张已经渲染好的图，没有可逐点变换的坐标。

若 GeoServer 出 WGS84 切片直接贴在高德底图上，在长三角一带会有约 **300~600m** 的系统性位移。城市尺度下肉眼可见，论文截图里是硬伤。

## 三条路线

### A · 服务端出 GCJ-02 切片（推荐）

在 GeoServer 侧配置自定义投影或出图时纠偏，前端直接贴。

- 代价：需后端配合，见协商清单 #4
- 优点：前端零成本，精度最好，无接缝

### B · 前端格网偏移近似

按 0.05° 格网计算偏移量，用 canvas 对瓦片重采样。

- 代价：瓦片边缘接缝、缩放级别切换时抖动、CPU 开销大
- 定位：仅作演示兜底，不进正式版本

### C · 曲面视图切换 WGS84 底图

该视图改用天地图或自托管 MapLibre，矢量点同步切换坐标系。

- 代价：与「高德为硬约束」冲突，需项目方同意作为**局部**例外
- 附带收益：同时解决内网/无外网演示场景

## 阶段 1 已落实的准备

地图内核按「可替换渲染后端」抽象（`MapAdapter` 接口，阶段 3 定稿），先实现高德适配器，为路线 C 保留插口。成本约 +5% 工作量。

## 判定节点

拿到协商清单 #4 的答复后确定路线。在此之前，`SurfaceLayerInfo.tile_crs` 字段已在类型层预留，Mock 默认返回 `'WGS84'`（最坏情况），保证问题在开发期就暴露而不是上线才发现。
